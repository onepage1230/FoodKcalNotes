# Spec：體重紀錄與追蹤（含減重期蛋白質下限）

- 狀態：待實作
- 決策依據：[ADR 0012](../decisions/0012-protein-floor-during-deficit.md)（蛋白質下限）；詞彙見 [GLOSSARY.md](../../GLOSSARY.md)；相關 ADR 0010（營養目標）
- 設計經過：本 spec 來自一輪 grill（Q1–Q21）與一輪出處查證，「Further Notes」列出沒有逐項討論過的預設值。

## Problem Statement

使用者設定減重計劃時只輸入一次體重，之後沒有地方記錄體重變化。要更新體重只能開「編輯計劃」改數字，這會覆蓋原本的體重、把計劃開始日重設成今天，所以預計達成日每次都從頭倒數，看不出實際進度，也看不到體重曲線。

蛋白質建議下限又隨體重計算（目前體重 × 1.1 g/kg）：體重一降，下限跟著降，但熱量赤字期正是蛋白質對保留肌肉最重要的時候，而且 1.1 g/kg 是維持期的建議量。

## Solution

新增獨立於減重計劃的**體重紀錄**：每天最多一筆，可補記、修改、刪除，不能記未來。設定頁新增「體重」卡片，可輸入體重、看趨勢圖（原始點加 7 天移動平均，有計劃時加計劃線）與紀錄清單，並顯示距離上次紀錄的天數。

**目前體重**改為最新一筆紀錄（沒有紀錄時才用計劃表單填的體重），TDEE 與蛋白質建議都用它。減重計劃的起始體重與開始日固定不動，預計達成日不隨紀錄變動，另外顯示實際進度與計劃線的差距。

減重計劃進行中，蛋白質建議下限改為 `max(1.4 × 基準體重, 1.1 × 起始與目前較大的體重)`，不隨減重下降，並附腎功能提醒（ADR 0012）。

## User Stories

### 記錄體重
1. 身為使用者，我想在設定頁輸入今天的體重並按「記錄」，以便不必開整個計劃表單就能更新體重。
2. 身為使用者，我想日期預設是今天，以便大多數時候只要輸入公斤數。
3. 身為使用者，我想同一天再記就覆蓋當天那筆，以便早晚各量一次時不會讓趨勢圖亂掉。
4. 身為使用者，我想補記過去某一天的體重，以便忘了當天記錄時事後補上。
5. 身為使用者，我想修改過去某一天的體重，以便更正輸入錯誤。
6. 身為使用者，我想刪除某一筆體重紀錄，以便移除量錯或誤記的資料。
7. 身為使用者，我想系統拒絕未來的日期，以便不會誤記到還沒到的日子。
8. 身為使用者，我想體重不合理（太小、太大、不是數字）時收到清楚的錯誤訊息，以便知道哪裡填錯。
9. 身為使用者，我想體重可以輸入到小數一位，以便記錄 0.1 公斤的變化。
10. 身為使用者，我想從紀錄清單點一筆就能改或刪，以便不必另外找入口。

### 沒有減重計劃也能用
11. 身為只想追蹤體重的使用者，我想不設減重計劃也能記體重和看趨勢圖，以便不被迫設定目標。
12. 身為沒有計劃的使用者，我想體重卡片只顯示趨勢與紀錄、不顯示達成日，以便畫面不出現沒意義的資訊。
13. 身為先記了體重才設計劃的使用者，我想設定計劃時「目前體重」自動帶入最新紀錄，以便不用重填。

### 趨勢圖
14. 身為使用者，我想看到體重隨日期變化的趨勢圖，以便知道整體走向。
15. 身為使用者，我想圖上有原始每日體重點，以便保留真實數據。
16. 身為使用者，我想圖上有 7 天移動平均線，以便不被水分造成的每日起伏誤導。
17. 身為有減重計劃的使用者，我想圖上看到計劃線，以便對照實際體重是否落後。
18. 身為使用者，我想文字顯示的「目前體重」是最新一筆原始值，而不是平均值，以便和體重計上的數字一致。
19. 身為只有一兩筆紀錄的使用者，我想圖仍然能正常顯示，不出現錯誤或空白。
20. 身為沒有任何紀錄的使用者，我想看到「還沒有紀錄」的提示，以便知道從哪裡開始。

### 提醒
21. 身為使用者，我想看到「距離上次紀錄 N 天」，以便知道該量體重了。
22. 身為使用者，我想超過 7 天沒記時用提醒色標示，以便注意到。
23. 身為使用者，我想不會收到推播通知，以便保持安靜。
24. 身為使用者，我想計劃卡片原有的「已到預計日期，請更新體重」提示保留，以便計劃到期時仍被提醒。

### 減重計劃的進度
25. 身為使用者，我想記錄新體重後預計達成日不改變，以便它代表原本的計劃，而不是每次記錄都被洗掉。
26. 身為使用者，我想看到「實際比計劃線高／低 X 公斤」，以便知道自己是超前還是落後。
27. 身為使用者，我想進度百分比用體重算（起始體重減目前體重，除以起始體重減目標體重），以便反映真正減了多少。
28. 身為使用者，我想體重回升時進度百分比跟著下降，以便數字誠實。
29. 身為使用者，我想最新體重達到或低於目標就顯示「已達成目標」，以便得到回饋。
30. 身為使用者，我想達成後若體重回升到目標之上，卡片自動回到進行中，不鎖定「已達成」，以便反映現況。
31. 身為使用者，我想計劃卡片顯示依目前體重計算的最新 TDEE 與「以目前目標每週約減 X 公斤」，以便判斷每日目標是否要調整。
32. 身為使用者，我想系統絕不自動改我的每日熱量目標，以便目標永遠是我自己決定的。
33. 身為使用者，我想計劃表單裡有紀錄時「目前體重」預填最新紀錄且唯讀，以便不會有兩個地方可以改同一個值。
34. 身為使用者，我想在需要時重新開始計劃（以目前體重與今天為新的起點），以便計劃失效或中斷後重來。

### 蛋白質下限
35. 身為減重中的使用者，我想蛋白質下限不隨體重下降，以便熱量赤字期保留肌肉。
36. 身為減重中的使用者，我想蛋白質下限比維持期高（1.4 g/kg），以便符合赤字期較高的需求。
37. 身為體重很重的使用者，我想下限永遠不低於國健署 RDA（1.1 或 1.2 g/kg 的實際體重），以便赤字期不會比維持期還少。
38. 身為體重很重的使用者，我想 1.4 倍只計入 BMI 25 對應體重加上超出部分的三分之一，以便目標不會高得不合理。
39. 身為減重中的使用者，我想蛋白質目標旁看到計算依據與出處的說明，以便知道這個數字從哪來、依據有多強。
40. 身為減重中的使用者，我想蛋白質目標旁有「腎功能不佳者請先諮詢醫師或營養師」的提醒，以便知道高蛋白的風險。
41. 身為已達成目標的使用者，我想蛋白質下限回到維持期的 1.1（71 歲以上 1.2）× 目前體重，以便目標符合維持階段。
42. 身為沒有減重計劃的使用者，我想蛋白質建議值維持「—」並提示設定計劃，以便行為與以前一致。
43. 身為手動覆寫過蛋白質目標的使用者，我想我的覆寫值不受影響，以便我自己的決定永遠優先。
44. 身為使用者，我想過去日子的蛋白質達標判定一律用現在的目標，以便畫面一致，不需回頭查當時的體重。

### 日誌與相容性
45. 身為朋友日誌的使用者，我想有自己的體重紀錄，彼此不可見，以便各自獨立。
46. 身為既有使用者，我想不需要資料遷移、不會被補上假的歷史紀錄，以便升級後資料保持原樣。
47. 身為既有使用者，我想還沒有任何紀錄時，目前體重仍然是計劃裡原本填的體重，以便升級後計劃和蛋白質目標行為不變（赤字期蛋白質下限會依 ADR 0012 升高）。
48. 身為使用者，我想匯出備份包含體重紀錄，以便備份完整。
49. 身為使用者，我想體重紀錄不影響食物庫、不影響連勝，以便功能互相獨立。

## Implementation Decisions

### 概念與資料
- 新概念：**體重紀錄**、**目前體重**、**基準體重**（已寫入 `GLOSSARY.md`）；**起始體重**＝儲存計劃當下的體重，之後不隨紀錄變動。
- 資料：每本日誌新增體重紀錄（日期、公斤），日期唯一；同一天再記即覆蓋。公斤數允許 25–300（與計劃驗證一致），保存到小數一位。日期格式與不得晚於伺服器本地「今天」的驗證，沿用餐點的日期規則。朋友日誌各自一份，食物庫仍共用主日誌（體重不涉及食物庫）。
- 計劃內的 `weight` 的語意固定為「起始體重」；`startDate` 為開始日。新增一個計劃欄位 `startGoal` 記錄起點設定當下的每日熱量目標（**起點每日目標**），只在首次儲存計劃、沒有紀錄時改了體重欄位（重設起點）或「重新開始計劃」時寫入；舊計劃沒有這個欄位時退回目前每日目標，不做遷移、讀取時不補寫。不補假歷史紀錄；沒有任何體重紀錄時，目前體重就是計劃裡的體重。
- 匯出資料新增體重紀錄。

### 目前體重與計劃計算
- 目前體重 = 最新日期的那一筆紀錄；沒有紀錄時 = 計劃的體重；兩者都沒有則為未知。
- TDEE、BMR、每週預計減重量用目前體重計算，顯示在計劃卡片上，不寫回設定。每日熱量目標絕不自動改。
- 預計達成日與總天數固定：以起始體重、開始日與起點每日目標推算，不隨體重紀錄、也不隨之後修改的每日目標改變。
- 進度百分比 = （起始體重 − 目前體重）÷（起始體重 − 目標體重），限制在 0–100%；體重回升則下降。
- 計劃線：從開始日的起始體重，依原計劃的每週預計減重量（起始體重算出的 TDEE 減起點每日目標）直線下降到目標體重，與預計達成日同一套語意，之後改每日目標不改計劃線。圖與文字顯示「實際比計劃線高／低 X 公斤」（以最新紀錄的日期對照計劃線）。
- 達成判定：最新一筆體重 ≤ 目標體重即「已達成目標」，每次即時判斷，不鎖定。

### 蛋白質下限（ADR 0012）
- 只在「有計劃且目前體重 > 目標體重」時使用新公式：`max(1.4 × 基準體重, RDA 倍率 × max(起始體重, 目前體重))`；RDA 倍率 1.1，71 歲以上 1.2。
- 基準體重：實際體重取起始與目前較大者；參考體重 = 25 × 身高(m)²；實際 ≤ 參考則用實際，否則用參考 + 0.33 ×（實際 − 參考）。
- 達成目標後回到 RDA 倍率 × 目前體重；沒有計劃仍為「未知」（不是 0）。結果四捨五入到整數 g。
- 蛋白質之外的四項建議值不變。覆寫值（`nutrientGoals`）規則不變。
- 建議值函式的輸入需要新增「目前體重」與「計劃是否進行中」；顯示用的依據文字隨情境（赤字期／維持期）切換，赤字期附腎功能提醒，並如實說明 1.4 是間接依據。

### API 與互動
- 讀取：回傳全部體重紀錄（日期遞增）與目前體重（含來源：紀錄或計劃）。
- 寫入：以日期為鍵新增或覆蓋一筆；刪除指定日期的一筆。驗證失敗回 400 與繁體中文訊息（例如「體重不正確，請輸入 25–300 公斤。」「不能記錄未來的日期。」）。
- 設定頁新增「體重」卡片：輸入欄位（日期預設今天）、「記錄」鈕、趨勢圖、紀錄清單（點一筆可改或刪）、「距離上次紀錄 N 天」（超過 7 天用提醒色）。首頁不動。
- 計劃卡片：有紀錄時表單裡的「目前體重」預填最新紀錄且唯讀；顯示進度百分比、與計劃線的差距、最新 TDEE 與每週預計減重量；「已到預計日期，請更新體重」提示保留。
- 趨勢圖：每日原始點 + 7 天移動平均（對每個有紀錄的日子，取該日與前 6 天內所有紀錄的平均）；有計劃時畫計劃線；只有一兩筆也要能顯示。
- 沒有計劃的日誌：體重卡片只顯示趨勢與紀錄，不顯示達成日與計劃線。

### 模組
- 資料層：體重紀錄的儲存、查詢、驗證。
- 路由：體重紀錄 API。
- 純函式（伺服器與前端共用或前端專用）：目前體重推導、蛋白質建議值（含基準體重）、計劃進度與計劃線、移動平均、距離上次紀錄天數。
- 前端：體重卡片、趨勢圖、計劃卡片與目標說明文字。

## Testing Decisions

### 好的測試
只測外部行為：給定紀錄與計劃，API 回什麼、純函式算出什麼數字、畫面文字是什麼。不測內部資料表的欄位細節。

### 測試層（seam）
經使用者確認：
1. **HTTP API**（既有的 `createApp` 依賴注入測試）：記、覆蓋、補記、刪除、拒絕未來日期與不合理體重、朋友日誌隔離、目前體重取最新一筆、沒有紀錄時用計劃體重、匯出包含體重紀錄、記體重不改每日熱量目標與計劃的開始日與起始體重。用注入的時鐘固定「今天」。
2. **純函式**（沿用既有純函式測試）：
   - 蛋白質：赤字期取較大值、BMI 36.8 附近的門檻、71 歲以上、達成目標後回到 RDA、沒有計劃為未知、起始體重大於目前體重時用起始體重。
   - 計劃進度：百分比、回升時下降、計劃線差距、達成與回升後取消達成。
   - 移動平均：缺日、單筆、跨月。
   - 距離上次紀錄天數與 7 天門檻。
不新增新型態的接縫。

## Out of Scope

- 體脂、腰圍等其他身體數據。
- 推播或其他主動通知。
- 體重變動時自動調整每日熱量目標。
- 依當時體重回頭重算過去日子的蛋白質達標判定。
- 跨日誌共用或彼此可見的體重紀錄。
- 匯入體重紀錄（只做匯出）。
- 國健署第九版 DRIs 若公布減重期數字，換算與調整留待之後。

## Further Notes

### 沒有逐項討論過的預設值（實作前請確認）
- **重新開始計劃**：Q5 只決定「記體重不重設起點，儲存計劃表單才重設」。但改活動量或目標體重時也會被當成重設，進度會被洗掉。本 spec 預設：儲存表單時改性別、年齡、身高、活動量、目標，都不動起始體重與開始日；另提供明確的「重新開始計劃」按鈕，才以目前體重與今天為新的起點（使用者故事 34）。這點沒有在 grill 中確認。
- **趨勢圖範圍**：預設顯示近 90 天，沒有範圍切換；紀錄清單顯示全部。
- **計劃線的每週減重量**：以起始體重的 TDEE 減起點每日目標（`startGoal`）推算，之後每日目標改變不回頭改計劃線與預計達成日；要依新目標重算請「重新開始計劃」。

### 出處與風險
- ADR 0012 的 1.4 g/kg 是間接依據；調整體重係數 0.33 已對 ESPEN/UEG 完整版指引原文核對（見 ADR 0012「依據」）；ESPEN ICU 指引原文仍未開啟。
- 部署後沒有覆寫過的赤字期蛋白質目標會自動升高；覆寫值不變。

### 交付階段（建議）
1. 體重紀錄資料層與 API（記、覆蓋、補記、刪除、驗證、匯出、朋友隔離）。
2. 目前體重推導與蛋白質建議值（ADR 0012，含達成目標與無計劃情境）。
3. 計劃進度改以體重計算（百分比、計劃線差距、達成即時判斷、最新 TDEE）與計劃表單唯讀體重、重新開始計劃。
4. 設定頁「體重」卡片與趨勢圖（原始點、移動平均、計劃線、距離上次紀錄提醒）。
5. 文件同步：README 中英、CLAUDE.md（新規則）、`GLOSSARY.md`、ADR 索引。
