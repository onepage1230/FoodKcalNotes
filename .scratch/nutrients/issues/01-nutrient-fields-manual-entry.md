# 01: 營養素欄位端到端貫通（手動輸入）

**What to build:** 使用者在結果頁可以為每項食物填寫、修改每 100g 的蛋白質、脂肪、碳水化合物、糖（總糖）與鈉；改克數時營養素與熱量一起即時重算；整餐顯示五項營養素總計，有未知項目時顯示「至少 X（N 項未知）」。保存後重新開啟、匯出備份都保留這些數值；功能上線前的舊餐點照常顯示與編輯，營養素顯示為未知。

這張同時是 prefactor：把「每項食物只有熱量一個數值」的假設，改成能承載多個數值，後續 ticket 只需要把資料填進來。欄位名稱、單位、範圍與 `null` 語意依 [spec](../../../docs/specs/nutrients.md) 與 ADR 0010。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 食物驗證接受並保留五個營養素欄位與 `estimated`，不再被白名單丟棄
- [ ] 營養素可為 `null`；超出合理範圍、三大營養素加總超過 100 g 的輸入被拒絕
- [ ] 每項、每餐的總量由程式依「克數 × 每100g ÷ 100」計算，回傳已知總量與未知項目數，未知不當 0
- [ ] 結果頁每項的營養素區塊預設收合，展開後可修改；改克數時即時重算
- [ ] 手動修改營養素時，該欄位移出 `estimated`，整項比照修改熱量的既有行為（標為使用者修改、不寫入食物庫）
- [ ] 手動新增食物時可只填熱量，營養素留空
- [ ] 整餐總計顯示五項，有未知時顯示「至少 X（N 項未知）」
- [ ] 匯出備份包含營養素與 `estimated`
- [ ] 沒有營養素欄位的舊餐點與舊食物照常讀取、編輯、匯出
- [ ] 日誌模組測試涵蓋：驗證、`null` 與 0 的差別、總計、改克數重算、舊格式相容、匯出
